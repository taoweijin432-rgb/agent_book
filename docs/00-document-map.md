## 1. 文档体系说明

本批文档定义系统的第一版可评审基线。文档描述业务目标、可验证要求、事实治理、逻辑架构、概念数据模型、上下文编译和正式提交协议；不等同于代码实现、完整 SQL DDL、部署手册或商业方案。

本项目采用以下基本口径：系统不承诺绝对不漂移，而是使漂移可检测、可阻断、可修复、可回滚和可量化。系统有两个叙事业务真实源：作者设计源与 Canon 叙事源；草稿暂存区用于承载候选内容，但不是第三个叙事业务真实源。任务、上下文包、审批、提交和审计可以是权威运行记录，但不构成第三个叙事业务真实源。结构化数据库为权威数据源，图关系和向量索引均为可重建投影。

## 4. 文档状态、版本与变更规则

文档状态为：

- **草案**：作者完成初稿，尚未完成评审，不作为实现承诺。
- **评审中**：有明确评审人和未决问题，允许提出修改意见。
- **正式**：经过批准，可作为实现、测试和评审依据。
- **废弃**：不再作为当前依据，但保留以支持历史追溯。

版本采用语义化规则：

- 主版本：权威边界、核心语义或兼容性发生破坏性变化。
- 次版本：新增兼容性内容、需求或对象，但不改变既有解释。
- 修订版本：澄清、勘误、链接和示例修正。

每次变更至少记录日期、变更摘要、原因、影响文档、评审状态和责任人/决策来源。正式文档被修改时，必须同步检查需求追踪、数据模型、架构和测试影响。

| 编号 | 问题 | 是否阻塞当前阶段 | 预计决策阶段 | 当前默认行为 |
