- 关联文档：[双真实源规范](04-dual-source-of-truth-spec.md)、[系统架构](05-system-architecture.md)、[叙事数据模型](06-narrative-data-model.md)、[正式提交协议](08-canon-commit-protocol.md)

## 1. 定位

上下文不是把数据库记录或历史正文简单拼接给模型，而是一个可追踪的查询、权限过滤、冲突处理、预算分配和编译过程。输入是 `06` 中的场景任务和一致读取边界。Context Bundle 必须在候选正文生成前完成编译；Generation Run 必须属于 Workflow Run 并引用固定的 Context Bundle，且该 Bundle 的 Scene Task Version 必须与 Workflow Run 的 Scene Task Version 完全相同。所有 Candidate Version 都必须能追溯实际适用的 Context Bundle：模型生成 Candidate 通过 Generation Run 追溯，修复或人工编辑 Candidate 通过同一 Workflow Run 内的前序 Candidate、Repair Record/Human Change Record 以及直接使用或继承的实际适用 Bundle 保持来源链；继承关系必须形成可审计关联，不能仅靠文字推断；非模型候选不要求伪造 Generation Run。Approval 使用的必须是当前最终 Candidate 实际绑定的 Context Bundle。每个进入模型的条目必须能追踪来源、版本、权限依据和入选原因；无法解释来源的内容不得作为事实性上下文注入。

## 2. 输入与分层

场景任务至少包含：小说/章/场景身份、由当前 `Canon Watermark` 确定的 Canon 一致读取状态、场景目标、参与人物、叙述视角、时间和地点、允许推进的剧情/伏笔、禁止泄露项、读者披露状态、文风要求、输出格式和预算。场景任务编译器应将秘密真相转换为安全约束，例如“本场景不得确认某人物死亡”“只能呈现指定线索”“保持某身份未确认”。

上下文分层如下：

1. **永久约束**：只注入经过安全投影的项目级规则、输出安全和硬权限。原始强结局、未来反转和秘密真相不得直接进入写作 Agent 上下文；它们必须先由场景任务编译器转换为安全约束。
2. **当前场景目标**：本场景需完成/禁止完成的目标、预期事件和节奏。
3. **人物与世界精确状态**：参与人物当前状态、知识边界、关系、位置、物品和可用能力。
4. **最近正文**：用于连贯性和指代消解的最近已提交内容；候选草稿需显式标识，不默认等同事实。
5. **相关历史事件**：按实体、因果、时间和大纲映射召回的历史事件。
6. **伏笔和未完成剧情义务**：安全投影后的待推进、待回收和逾期提醒，不直接泄露秘密答案。
7. **文风与写作技巧资产**：作者批准的样例、叙事视角、节奏和禁用表达；仅作为风格约束，不证明事实。

各层需带优先级和来源。永久约束与当前状态冲突时，不能靠拼接顺序解决，应进入冲突处理/人工确认。

## 3. 检索路由与使用边界

推荐路由：

1. 用结构化查询锁定小说、版本、场景参与实体、时间范围、权限和状态；结构化约束优先。
2. 用关键词/全文检索召回明确名称、别名、事件类型、章节和正文证据。
3. 在候选范围内用向量检索召回语义相关历史片段或文风资产。
4. 按需使用图关系投影查询关系路径、因果候选和实体邻接。
5. 所有索引命中回到结构化权威数据核对有效性、版本和权限。

向量相似度只能作为召回信号，不能证明事实成立。图边和向量记录不是权威源，索引落后或错误时以结构化数据为准。秘密、知识状态、人物视角和禁止项应先过滤，再允许进入后续召回；不得先把全库秘密召回后再依靠 Prompt 要求模型忽略。

## 4. 预算、排序与裁剪

上下文包应按固定预算编译，而不是无限追加。预算至少拆分为：永久约束、场景目标/输出要求、当前状态、最近正文、历史事件、伏笔义务、文风资产、工具/格式说明和安全余量。具体比例和最大 token 数待模型窗口与基准测试确定。

排序优先级建议为：硬约束与安全边界 > 当前场景目标 > 参与人物/地点/物品精确状态 > 最近正文 > 与目标直接相关的历史事件 > 伏笔和大纲义务 > 文风资产 > 弱相关背景。裁剪只能丢弃低优先级或重复内容，不得裁剪导致状态、权限或禁止泄露条件无法解释。

## 5. 去重、冲突和不确定性

去重以稳定对象身份、事件身份、正文版本和语义指纹组合判断；同一事实的不同证据可合并展示，但必须保留所有关键来源。不同版本不能无标识地合并。

发现冲突时，组装器应：

- 先比较权威层级和版本有效性。
- 将“设计约束 vs 已提交事实”标记为需处理的跨源冲突，而不是选择一方静默覆盖。
- 将互相矛盾的时间、关系或状态并列呈现并阻止自动生成，除非规则已定义合法并存。
- 对不确定事实使用待确认标签，不转成确定性陈述。
- 记录冲突 ID、涉及版本和未采用内容；不得把被裁剪内容伪装成不存在。

## 6. 权限、视角与秘密保护

上下文生成遵循最小必要原则：写作 Agent 只能读取当前场景所需信息。权限过滤分别考虑：Agent 权限、当前叙述视角、人物知识/信念、当前读者披露状态和日志输出权限。人物视角过滤至少检查叙述者可观察内容、人物当时的 `known_true`/`known_false`/`believed_true`/`believed_false`/`unknown` 状态、可合法推断内容和禁止知道内容。秘密真相不得作为普通条目注入；只能编译为安全任务约束。

权限过滤覆盖正文、结构化事实、图/向量召回、错误消息、Prompt 变量、Trace、日志和评测导出。校验服务可以在受控权限下看到更多事实，但其输出给写作 Agent 仍必须经过安全投影。日志记录来源和策略版本即可，不默认记录秘密原文。

## 7. Context Bundle 与 Context Item 的可追踪字段

Context Bundle 是在候选正文生成前编译出的不可变包。包级字段概念上包括：

- `bundle_id`；
- 整个包的内容哈希；
- Context Compiler 版本；
- 创建时间；
- 绑定的 `Author Design Revision` 和 `Canon Watermark`，由二者共同固定一致读取边界；
- 预算与策略版本；
- 生成它的 Scene Task 和后续引用它的 Generation Run。

每个 Context Item 的条目级字段可以包括：

- `context_item_id`；
- 来源对象与来源版本；
- 可见性处理方式；
- 证据定位；
- 排序分数；
- token 或字符预算；
- 进入原因；
- 截断或摘要方式；
- 优先级、是否裁剪、冲突状态和脱敏状态。

`bundle_id`、整个包的内容哈希、Context Compiler 版本、包级预算和包级策略版本属于 Context Bundle 的包级信息，不应被表述为每个条目都必须拥有的独立字段；如果条目需要引用它们，只能明确为外键或冗余审计字段。Candidate Version 不在 Context Bundle 创建时直接生成或强制绑定 Generation Run；每个 Candidate 仍必须通过实际来源链追溯具体适用的 Context Bundle，并明确直接使用新 Bundle 或继承前序 Candidate 的 Bundle 及其审计关联；修复/人工编辑的前序 Candidate 默认必须属于同一 Workflow Run，非模型候选不得为了满足基数伪造 Generation Run。

被隐藏或重写的原始来源引用只能存在于受限审计元数据，不得进入模型可见的上下文载荷。写作 Agent 不得通过条目字段、调试信息、解释文本或工具结果恢复被隐藏的设计秘密；审计人员的可见性必须与写作 Agent 的可见性分开。

上下文包一旦用于生成，应不可静默修改；修订应产生新包并关联新的 Generation Run。

## 8. 可重放与模型窗口兼容

可重放分为两种不同目标：

1. **使用已保存上下文包重放模型调用**：固定 `bundle_id`、内容 hash、上下文版本、Prompt/模型/工具版本和参数，重建原始输入与执行链路；外部模型不保证逐字复现。
2. **重新执行上下文组装并比较差异**：重新运行结构化查询、关键词/向量/图召回、权限过滤和裁剪，输出新上下文包并与原包比较。如果索引版本变化，或 Author Design Revision、Canon Watermark、权限策略、编译器版本发生变化，不得声称与原上下文完全一致。

如果允许候选草稿作为最近正文，必须记录其草稿分支、候选版本和依赖关系；当前是否支持后一份草稿依赖前一份未提交草稿仍待确认，见 [文档地图中的 OQ-003](00-document-map.md)。在该问题决定前，草稿默认不作为 Canon 事实，也不进入普通事实上下文。

模型上下文窗口变化时，保持语义分层和条目优先级稳定；通过版本化预算策略调整裁剪，而不是改变事实权威。窗口变大不意味着泄露更多秘密或无条件加入全书；窗口变小不得裁剪硬约束、视角权限和当前状态。预算策略升级需用同一基准集比较冲突率、秘密泄露率、成本和质量变化。
