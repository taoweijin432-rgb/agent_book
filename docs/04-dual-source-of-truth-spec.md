## 1. 核心定义

系统有且仅有两个**叙事业务真实源**：

1. **作者设计源（Author Design Source）**：作者明确设计或批准的世界规则、人物设计、剧情主线、大纲、秘密、伏笔和结局约束。它表达“作品应该如何设计”，不是正文已经发生的证明。
2. **Canon 叙事源（Canon Narrative Source）**：正式提交的 Canon 正文版本，以及从 Canon 正文确认的结构化事件、事实、叙事陈述和状态变化；当前状态投影可由权威事件和事实重建。它表达“叙事中已经被确认或呈现为何种内容”，不等于每一句叙事陈述都是客观世界事实。

任务、上下文包、审批、提交和审计可以是权威运行记录，但不构成第三个叙事业务真实源。草稿暂存区承载候选正文、候选事件和状态变更提案，也不是第三个叙事业务真实源；草稿、候选抽取、检索索引、Prompt 内容和模型输出在正式提交前均不得视为 Canon。

两个叙事业务真实源不能直接双向同步。任何跨源影响必须通过明确的映射关系、受控事件、修订或约束例外记录和提交服务表达，并保留来源与版本。

## 2. 数据边界、读写者与版本

| 区域 | 主要内容 | 允许写入者 | 允许读取者 | 权威性 |
|---|---|---|---|---|
| 作者设计源 | 规则、设计、目标、秘密、伏笔和约束 | 作者；经授权的设计服务；规划提案经作者确认后 | 作者、规划 Agent、校验服务、提交服务；写作 Agent 仅读取场景安全投影 | 真实源 |
| Canon 叙事源 | 正式提交的 Canon 正文版本、叙事陈述、已确认事件/事实、状态变化和可重建状态投影 | 仅提交服务；作者修改也必须通过修订/补偿/强制覆盖协议 | 作者、规划/校验/上下文服务；写作 Agent 仅读取授权快照 | 叙事业务真实源 |
| 草稿暂存区 | 候选正文、抽取候选、状态变更提案、修复候选 | 写作 Agent、校验/修复服务、作者编辑 | 相关用户和服务 | 非 Canon |

对象使用稳定身份，不因重写或别名变更而复用另一个对象的身份。Author Design Source 保留 Author Design Revision；当前单 Canon 主分支不建立独立 Canon 版本实体。成功 Canon Commit 按严格单调递增的 Canon Commit Sequence 排序，Canon Watermark 表示截至某个成功序列可见的 Canon 快照边界；它不是第三真实源或独立叙事对象。上下文读取应固定到 Design Revision 和 Canon Watermark；提交服务必须检查绑定快照未被不兼容修改。

## 3. 状态变化规则

作者设计对象及伏笔设计只表达草案、已确认/生效、已替代、已废弃等设计生命周期；状态变化由作者或受控设计服务发起。指定 Canon Watermark 下的埋设、推进、回收、违反或完成均不写回 Author Design Revision，而由 Design Fulfillment State 根据 Canon Evidence 派生。Canon 叙事对象的执行状态与业务语义分开：候选/待确认属于草稿或执行域，已提交才属于 Canon；被修订/失效表示其历史记录仍存在但不再作为当前有效投影。

候选正文只有同时满足以下条件才可进入 Canon 叙事源：正文通过必要硬约束校验；候选中的叙事陈述、状态变更提案和事件证据已经按规则处理；所需人工审批或自动审批已完成；提交服务在同一逻辑事务内写入 Canon 正文、事件、事实、状态变化和投影 Outbox；审计记录完整。任一条件不满足，候选仍停留在草稿暂存区或被拒绝。

正文中的叙事陈述可以是客观陈述、谎言、传闻、误认或不可靠叙述；正文出现一句话，不等于其描述的内容已经成为客观世界事实。只有通过提交和确认规则的内容才能成为相应层级的 Canon 事件、事实或状态。

## 4. 设计修改的影响

作者修改既有设计不会自动重写历史 Canon，也不会静默修改已提交事实。系统必须：

1. 建立新的 `Author Design Revision` 并记录变更差异和生效范围。
2. 评估与 Canon 事件/事实、未完成大纲、伏笔、未来场景的潜在冲突。
3. 将影响标记为需要修订、允许并存、待作者确认或不影响历史。
4. 对未来上下文使用生效的 `Author Design Revision`，对历史回放使用原版本，除非作者发起受控重演。
5. 如需改变既有 Canon，走已发布章节修订、约束例外或反向/补偿提交协议，保留旧内容的失效/替代记录。

正文事实与设计意图不一致时，不得自动把正文改写为设计，也不得自动把设计降级为 Canon。应先分类为设计漂移、作者有意改稿、叙事陈述与客观事实的区别或 Canon 错误，再由作者/审批流程决定修订设计、修订正文或接受带审计的约束例外。

## 5. 大纲目标与事实映射

大纲节点属于 Author Design；目标是否已经在故事中实际完成，其证据必须来自 Canon 叙事源中的已提交 Canon 正文版本、Story Event、Canon Fact 或 State Transition。目标与 Canon 内容之间的映射关系、完成度评估和流程状态可以属于权威映射记录或 `Workflow Run`，但“完成度评估记录”本身不自动成为故事世界中的 Canon Fact。Author Design 表达作者意图，Canon 表达故事已经发生或成立的内容。目标“完成”不能仅由模型说“已完成”或文本长度推断；必须有配置的 Canon 证据或人工确认。

## 6. 伏笔与秘密生命周期

伏笔设计由作者创建，只能经历设计生命周期：草案 → 已确认/生效 → 已替代或已废弃。指定 Canon Watermark 下是否已经埋设、推进、回收、违反或完成，由 Design Fulfillment State 根据 Canon Evidence 派生；Canon 证据不得直接回写 Author Design Revision。伏笔设计被废弃或替代也保留原因，避免在后续上下文中被误判为遗漏。

秘密相关概念分开建模：作者设计秘密（作者设计源中的真相及揭示约束）、Agent 可见范围（本场景允许注入的安全投影）、人物知识或信念（人物在故事时间上的认知状态）、读者披露状态（正文已经向读者确认/暗示到的程度）。四者不得由一个“秘密状态”字段或同一语义替代。秘密真相在场景任务编译时转换为安全约束，例如“不得在本场景确认 X”“只能呈现线索 Y”“保持某身份未确认”，而不是把真相直接放入写作 Agent 的普通上下文。授权校验上下文和日志也必须按权限与脱敏策略处理。

## 7. 允许传递的事件与禁止直接同步

允许从作者设计源传递到执行域的内容包括：`Author Design Revision`、场景目标、约束、允许/禁止条件、伏笔任务、秘密安全投影和完成判据。允许从 Canon 叙事源反馈到设计/规划域的内容包括：已提交事件、叙事陈述的确认结果、状态事实、目标完成证据、伏笔推进证据和冲突报告。上述传递必须带映射 ID、`Author Design Revision`、`Canon Watermark`/成功 `Canon Commit Sequence`、`Workflow Run` 或任务 ID。

禁止：

- 写作 Agent 直接将候选正文或“模型认为发生了”的事实写入 Canon 叙事源。
- 通过双向同步脚本自动用正文覆盖设计，或用设计覆盖历史正文。
- 用向量命中、图边或相似度直接升级事实。
- 将草稿缓存、Prompt 内容或模型输出当作第三个叙事业务真实源。
- 让任意 Agent 直接操作任意表或绕过领域服务。

## 8. 版本、运行和提交记录命名

为避免把不同生命周期混称为“批次”，本规范使用以下术语：

- `Author Design Revision`：作者设计源的一次修订版本；草案阶段可编辑，确认/冻结后不可原地修改。
- `Canon Commit Sequence`：当前单 Canon 主分支中，成功 `Canon Commit` 的严格单调递增顺序；不承诺数值连续或无空洞。
- `Canon Watermark`：截至某个成功 `Canon Commit Sequence` 可见的 Canon 快照边界；由成功提交确定，不是独立叙事对象，也不是第三真实源。
- `Canon Commit`：将候选正文、确认结果和状态变化正式写入 Canon 的提交记录。
- `Workflow Run`：一次生成、校验、审批或修复流程的运行记录。
- `Projection Task`：一个需要完成的逻辑投影工作；普通任务来源于一个 `Projection Outbox`，重建任务来源于一个 `Projection Rebuild Record`。
- `Projection Attempt`：一次领取、执行、超时、失败或成功的投影尝试；重试产生新的 Attempt，不产生语义重复的有效 Task。

只有在确实表示批处理任务时才使用“批次”；上述记录不应被统称为同一批次。

## 9. 回滚与重演

回滚针对一个 `Canon Commit` 或修订范围产生新的反向/失效记录，不删除原审计证据。回滚后的 `Derived Current State`、`Reader Disclosure State`、`Derived Timeline View` 和 `Design Fulfillment State` 由成功提交产生的 `Projection Outbox` 驱动重算；Projection Task/Attempt 在事务外执行。原始 Outbox 不被伪造或当作可随意重建的派生结果。

重演必须固定原始 `Author Design Revision`、`Canon Watermark`、场景任务、Context Bundle 的实际编译内容、Prompt 版本、模型版本、工具版本、参数和随机性相关配置，并保留原始输入与外部调用结果。可以重建原始输入和执行链，但不承诺重新调用外部模型得到逐字相同输出；Candidate Version 原始正文必须保留。旧 `Workflow Run` 重新提交时必须再次检查当前 Canon Watermark、幂等键和版本冲突，不得默默覆盖新事实。
