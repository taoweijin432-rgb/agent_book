## 1. 项目背景与核心问题

长篇小说的难点不是单次生成一段通顺文字，而是在百万字级叙事中持续维护设计意图、已确认事实、人物状态、知识边界、时间线、地点、物品、关系、因果、伏笔和文风。单纯依靠更长的 Prompt、向量相似度或人工记忆，难以回答“这一事实何时被确认、来自哪一版设计、谁知道它、是否已经发生、能否在本场景中被写出”等问题。

本项目拟建立一个可验证的 AI 写作系统，使写作 Agent 在受控的场景任务中生成候选正文，并由校验与提交机制决定哪些内容可以成为 Canon 事实。目标不是宣称绝对不漂移，而是让漂移具有可检测、可阻断、可修复、可回滚和可量化的工程路径。

## 2. 目标用户与核心价值

首要用户是希望长期维护原创长篇小说的作者。系统还服务于需要规划、审校或维护作品一致性的人工协作者，但当前不以团队协作为核心范围。

核心价值包括：

- 将作者的世界规则、人物设计、大纲、秘密、伏笔和结局约束结构化管理。
- 将已正式提交至 Canon 叙事源的故事事件和状态作为可审计内容保存。
- 在写作前生成与场景、人物视角和权限相匹配的上下文任务，而不是无差别暴露全书资料。
- 在正文正式生效前检测硬冲突和可量化的软质量问题。
- 允许作者人工干预、局部修复、回退和重演，保留完整版本与证据链。

## 3. 系统边界

系统边界包含：作者设计管理、Canon 叙事管理、场景规划、候选正文生成、一致性检查、局部修复、人工审批、正式提交、版本回退、索引投影、审计和质量评测。

系统不替代作者对文学目标的最终判断，不把模型输出直接视为 Canon 事实，不把向量检索结果直接视为 Canon 事实，也不把隐藏剧情真相直接提供给写作 Agent。关系数据库中的结构化数据是权威数据源；图和向量索引仅用于检索或查询投影，并可由权威数据重建。

## 4. 当前阶段范围

当前阶段优先建设单用户、单项目、可验证的核心写作闭环：

1. 建立作者设计源、Canon 叙事源和草稿暂存区的清晰边界。
2. 支持小说—卷—章—场景的基础叙事层级。
3. 支持人物、地点、组织、物品、世界规则、大纲、伏笔、秘密和结局约束等核心设计对象。
4. 支持场景任务编译、上下文组装、候选正文、状态变更提案、校验、审批和原子提交。
5. 建立硬冲突阻断、软质量评分、审计和可重放机制。
6. 以可重建的检索投影辅助召回，但不引入其作为事实权威。

## 5. 明确不做的事项

当前阶段不纳入：

- 多租户、订阅、计费、商业化套餐和分享社区。
- 面向大规模协作组织的复杂组织权限。
- 以 Agent 数量作为产品目标的多 Agent 编排。
- 在尚未验证核心闭环前引入微服务、消息队列、复杂图数据库或其他重型中间件。
- 完整 SQL DDL、生产部署拓扑和具体云厂商绑定。
- 对所有文学质量进行自动化、无争议的终局判断。

## 6. 分阶段建设目标

**阶段 0：设计基线。** 完成本批文档、术语、需求编号、数据边界、提交协议和开放问题清单。

**阶段 1：最小可验证闭环。** 在单项目中完成设计对象、场景任务、候选正文、硬校验、人工审批和正式提交；先以关系数据库或等价结构化存储为权威源。

**阶段 2：质量与可观测性。** 完善事件/状态抽取、漂移指标、重放、版本回退、成本和人工修改评测，建立基准测试集。

**阶段 3：检索与规模优化。** 在权威数据稳定后，按实际召回瓶颈选择关键词、向量或图投影；验证百万字级项目的分层归档、增量索引和上下文预算。

**阶段 4：扩展能力。** 根据真实使用数据评估协作、更多出版流程和外部集成，不能将这些能力倒推为当前核心假设。

## 7. 工程定义

“百万字级长篇”是容量与维护目标，不是一次将一百万字塞入模型上下文。它至少意味着：系统能在分卷、分章、分场景的分层结构中管理约一百万字及以上的累计正文，并通过结构化 Canon 事实、事件、状态和可重建索引，支持在可接受成本和耗时内为当前场景召回相关信息。具体容量、延迟和成本阈值应由阶段 2/3 基准测试确定。

“不漂移”不是绝对保证。工程上应定义为：对已声明的约束和已提交事实，系统能够识别可验证的违反情况；在硬错误发生时尽量阻断正式提交；对软质量问题给出可解释的证据和修复建议；允许作者确认例外、回滚错误提交并统计趋势。任何阈值在基准测试前都标记为“待通过基准测试确定”。

## 8. 规模验证层级

以下规模均指项目累计正式正文规模，不代表单次模型上下文长度，也不要求把全部正文放入一次模型调用：

- **10 万字**：功能与回归基准，用于验证核心闭环、冲突检测、回滚和重放。
- **100 万字**：完整长篇基准，用于验证分层事实、检索召回、上下文编译和长期一致性。
- **500 万字**：目标压力基准，用于评估容量、归档、索引重建、成本和耗时趋势。

各层级的正式性能、成本、耗时和质量阈值均待通过基准测试确定，不在本阶段预设承诺值。

## 9. 成功与失败标准

成功标准：

- 需求、架构、数据和提交协议可以互相追踪，且没有把草稿当成第三个叙事业务真实源。
- 关键硬冲突可在正式提交前被检测并按规则阻断或进入人工审批。
- 每个进入模型的事实性上下文可追溯到来源、版本、权限和入选理由。
- Canon 正文版本、事件和状态变更具有明确提交边界、幂等行为和审计记录。
- 在真实基准集上能量化硬冲突、秘密泄露、时间线冲突、人工修改、成本和耗时趋势。

失败标准：

- 依赖“更强模型”而无可验证的事实来源、提交边界或回滚能力。
- 写作 Agent 可以直接修改 Canon 叙事源或任意数据表。
- 将图数据库、向量数据库或相似度当作事实证明。
- 隐藏信息因上下文拼接、检索、日志或错误提示泄露。
- 为追求技术复杂度而牺牲单用户核心闭环的可验证性。
